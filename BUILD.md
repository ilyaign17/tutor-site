# Статический CSS

Сайт использует Tailwind CSS 3.4.17 только при разработке. GitHub Pages отдаёт
готовый `css/styles.css`; Node.js и сборка на сервере не нужны.

## Пересборка

После первого получения проекта установите зависимости из lock-файла:

```sh
npm ci
```

После добавления или изменения Tailwind-классов в `index.html`, настроек в
`tailwind.config.cjs` или директив в `css/tailwind.css` выполните:

```sh
npm run build
```

Сохраняйте с изменениями сайта и обновлённый `css/styles.css`.
Команда `npm run build:css` также доступна и выполняет ту же сборку.
Для изменения только текстов, изображений или существующих кастомных правил
в `<style>` пересборка не требуется.

## Порядок стилей

Кастомные стили остаются в `index.html` без переноса и переработки.
Подключение `css/styles.css` расположено после них намеренно: прежний Play CDN
добавлял сгенерированные стили именно в конец `<head>`. Перестановка подключения
может изменить каскад и внешний вид сайта.

Сборка сканирует `index.html`, включая полные имена Tailwind-классов в скриптах.
Текущие динамические классы `nav-ready`, `is-open`, `is-enhanced` и `is-active`
описаны кастомным CSS и не требуют safelist. Если в будущем появятся динамически
собираемые имена утилит, добавьте полные имена в `safelist` конфигурации.

Путь `./css/styles.css` работает на основном домене и при размещении сайта
в подпапке GitHub Pages. Настройки публикации менять не требуется.
